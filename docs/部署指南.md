## 0. 环境要求

**运行环境**

| 项 | 要求 |
|---|---|
| Python | 3.8 及以上（推荐 3.10+） |
| 第三方运行时依赖 | **无需任何 pip 包**（SQLite 模式） |
| 操作系统 | Windows 10+ / Windows Server 2016+ / Linux（systemd） |
| 内存 | 512 MB 起步，50 人以内 1 GB 足够 |
| 磁盘 | 程序约 30 MB + 上传文件 + 数据库 |

**验证 Python**

```bash
python --version
```

> Windows 上如果 `python` 打开了微软商店，说明没装真正的 Python。
> 请从 [python.org](https://www.python.org/downloads/) 安装，安装时勾选 **Add Python to PATH**。

**开发/打包环境**（仅打包 EXE 时需要）

```bash
pip install pyinstaller
```

## 1. 源码方式部署

### 1.1 获取代码

```bash
git clone https://github.com/1706691925/yunliaochat.git yunliao
cd yunliao
```

或直接解压发布包。

### 1.2 启动

```bash
# Windows
启动服务器.bat

# 或手动
python app.py

# Linux
chmod +x 启动服务器.sh && ./启动服务器.sh
```

首次启动会自动完成：建库建表 → 写入演示数据 → 生成随机管理员口令。

控制台会打印：

```text
  版本：1.1.2
  系统名称：云聊
  数据目录：/path/to/yunliao/data
  监听地址：0.0.0.0:8080
  本机访问：http://127.0.0.1:8080
  内网访问：http://192.168.1.10:8080
  用户总数：8    在线：0
  ★ 初始管理员：admin / Lc@25572d9 （已写入 data/初始管理员密码.txt）
```

### 1.3 首次登录

1. 浏览器打开 `http://<服务器内网IP>:8080`
2. 用 `admin` + 控制台显示的口令登录
3. **立即修改密码**（右上角头像 → 个人设置）
4. 进入「管理控制台」→ 系统设置，改站点名称、关闭自助注册

### 1.4 命令行参数

```bash
python app.py --help
```

| 参数 | 说明 |
|---|---|
| `--host 0.0.0.0` | 监听地址。仅本机用 `127.0.0.1` |
| `--port 8080` | HTTP 端口 |
| `--no-browser` | 不自动打开浏览器（服务器必加） |
| `--reset-admin` | 重置 admin 密码为新的随机值后退出 |
| `--https` / `--cert` / `--key` | 启用 HTTPS 并指定证书 |
| `--set-theme blue\|bluepink` | 直接切换站点配色后退出 |
| `--data-dir <path>` | 指定数据目录（多实例/迁移时用） |
| `--quiet` | 减少控制台输出 |

### 1.5 数据目录

所有可变内容都在 `data/` 下：

```text
data/
├── config.json          全部配置（站点信息、策略、数据库引擎…）
├── app.db               SQLite 数据库（MySQL 模式下无此文件）
├── mysql/               MySQL 数据目录（仅 MySQL 模式）
├── files/               用户上传的文件
├── backups/             备份文件
├── logs/                运行日志
└── 初始管理员密码.txt     仅在首次初始化时生成
```

> **迁移服务器 = 停服务 + 整个 `data/` 目录拷过去 + 启动。**
> 无需重装、无需导库（除非换了数据库引擎，见 §3.4）。

## 2. 打包成单个 EXE

适合交付给「电脑上没装 Python」的机器。

```bash
pip install pyinstaller
构建EXE.bat          # Windows
# 或
bash 构建EXE.sh      # Linux
# 或
pyinstaller build.spec
```

产物在 `dist/云聊.exe`（约 10–20 MB），双击即可运行。

**注意事项**

- 打包产物**不含** MySQL。若要用 MySQL 模式，请把解压好的 `vendor/mysql`
  放在 exe 同目录，或改用 SQLite 模式（默认）。
- 数据目录默认在 exe 同级的 `data/`。
- 首次运行 exe 同样会生成 `data/初始管理员密码.txt`。
- Windows 可能提示「未知发布者」：这是未做代码签名的正常现象，
  内网分发可让用户点「更多信息 → 仍要运行」。

## 3. 数据库：SQLite 与 MySQL

### 3.1 怎么选

| 场景 | 建议 |
|---|---|
| 个人 / 小团队（≤ 50 人）/ 演示 / 教学 | **SQLite**（默认） |
| 几十到几百人、写操作较多 | 两者均可，SQLite 加 WAL 已够用 |
| 需要标准 SQL 运维、异地只读副本、已有 MySQL 运维体系 | **MySQL** |
| 磁盘空间紧张 | SQLite（MySQL 会多占数百 MB） |

> 云聊的业务量（消息、文件元数据）通常很小，SQLite 在几百人规模内表现良好。
> 若你的瓶颈是「未读计数」这类查询，本项目已用冗余计数列优化，与引擎无关。

### 3.2 使用 SQLite（默认）

无需任何操作。数据在 `data/app.db`。

**备份**：停服务后直接拷贝 `data/app.db`（若存在 `app.db-wal` / `app.db-shm` 一并拷贝）。

### 3.3 使用 MySQL

**第一步：准备运行时（只需一次）**

```bash
# 从 MySQL 官网或国内镜像下载 Windows ZIP 版（约 210 MB）
# https://mirrors.aliyun.com/mysql/MySQL-8.0/mysql-8.0.28-winx64.zip

python tools/setup_mysql.py --zip /path/to/mysql-8.0.28-winx64.zip
```

脚本会把它解压到 `vendor/mysql/`（会剥掉 ZIP 里的单层目录）。

**第二步：切换引擎**

编辑 `data/config.json`：

```json
{
  "db_engine": "mysql"
}
```

**第三步：启动**

```bash
python app.py
```

程序会自动：
1. 用 `mysqld --initialize-insecure` 初始化 `data/mysql/`
2. 启动 mysqld（只监听 `127.0.0.1`，端口默认 33070，被占用则自动避让）
3. 建库 `yunliao`、建用户 `yunliao`、授权
4. 建 31 张表

**可选配置**（`data/config.json`）：

```json
{
  "db_engine": "mysql",
  "mysql_port": 33070,
  "mysql_database": "yunliao",
  "mysql_user": "yunliao",
  "mysql_password": ""
}
```

> **关于密码**：默认空密码。因为 mysqld 只监听回环地址、端口随机避让，
> 外部无法连接。若你的机器有不受信任的本地用户，建议设置 `mysql_password`。
> 修改密码后需重启一次，程序会用 root 重新 `ALTER USER` 同步。

> **关于中文路径**：Windows 版 mysqld 用 ANSI 接口解析自身路径，
> 路径含中文会启动失败。程序会自动在 `%LOCALAPPDATA%\YunliaoMySQL\` 下建立
> 目录联接（junction）绕过该限制，数据仍留在 `data/mysql/`。
> 但仍**建议把程序放在纯英文路径**（如 `D:\yunliao`），最省事。

### 3.4 从 SQLite 迁移到 MySQL（或反向）

**SQLite → MySQL**

```bash
# 先切到 mysql 引擎并至少启动一次（让表结构就绪）
python tools/migrate_sqlite_to_mysql.py --src data/app.db
```

脚本会逐表拷贝数据、保留原 id，并把 `AUTO_INCREMENT` 对齐到 `max(id)+1`。

**任意方向（推荐，通用）**

用后台的备份/恢复功能，它导出的是引擎无关的 `.sql`：

1. 原引擎下：管理控制台 → 数据库 → 导出备份
2. 改 `db_engine`
3. 启动后：管理控制台 → 数据库 → 恢复，选择刚导出的 `.sql`

## 4. 配置 HTTPS

**仓库不附带任何证书。**请使用你自己的域名和证书。

### 4.1 有域名（推荐）

用 [acme.sh](https://github.com/acmesh-official/acme.sh) 或 certbot 申请 Let's Encrypt 免费证书：

```bash
acme.sh --issue -d chat.your-domain.com --standalone
```

拿到 `fullchain.pem` 和 `privkey.key` 后放进 `cert/` 目录：

```text
cert/
├── fullchain.pem
└── privkey.key
```

编辑 `data/config.json`：

```json
{
  "https_enabled": true,
  "https_port": 8443,
  "cert_file": "cert/fullchain.pem",
  "key_file": "cert/privkey.key"
}
```

重启。之后 HTTP 与 HTTPS 同时可用。

或者在后台「系统设置 → 安全与访问」里在线填写路径并勾选启用。

### 4.2 只用内网 IP（自签证书）

内网 IP 无法申请公共 CA 证书，只能自签：

```bash
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
  -keyout cert/privkey.key -out cert/fullchain.pem \
  -subj "/CN=192.168.1.10" \
  -addext "subjectAltName=IP:192.168.1.10"
```

把 IP 换成你的服务器地址。浏览器首次访问会提示「证书不受信任」，
需手动信任或导入到单位域策略的受信任根证书。

> HTTPS 的真正价值在于**加密传输**（防止同网段抓包看密码）。
> 自签证书同样能加密，只是浏览器会警告。

### 4.3 用 Nginx 反向代理（生产推荐）

让 Nginx 处理 TLS，云聊只监听回环：

```nginx
server {
    listen 443 ssl;
    server_name chat.your-domain.com;

    ssl_certificate     /etc/nginx/cert/fullchain.pem;
    ssl_certificate_key /etc/nginx/cert/privkey.key;

    client_max_body_size 100m;      # 要 >= 云聊的 max_upload_mb

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket 必需
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
    }
}
```

云聊侧：

```bash
python app.py --host 127.0.0.1 --port 8080 --no-browser
```

并在 `data/config.json` 中设置 `"trust_real_ip": true`，
这样审计日志里记录的是真实客户端 IP 而非 `127.0.0.1`。

> **务必保留 WebSocket 的两个 `proxy_set_header`**，否则聊天无法实时收到消息。

## 5. 开机自启与守护

### 5.1 Linux（systemd）

```ini
# /etc/systemd/system/yunliao.service
[Unit]
Description=Yunliao 云聊
After=network.target

[Service]
Type=simple
User=yunliao
WorkingDirectory=/opt/yunliao
ExecStart=/usr/bin/python3 /opt/yunliao/app.py --host 0.0.0.0 --port 8080 --no-browser --quiet
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo useradd -r -s /sbin/nologin yunliao
sudo chown -R yunliao:yunliao /opt/yunliao
sudo systemctl daemon-reload
sudo systemctl enable --now yunliao
sudo systemctl status yunliao
journalctl -u yunliao -f
```

### 5.2 Windows（任务计划程序）

1. 打开「任务计划程序」→ 创建任务
2. 常规：勾选「不管用户是否登录都要运行」+「使用最高权限运行」
3. 触发器：启动时
4. 操作：`pythonw.exe`，参数 `app.py --no-browser --quiet`，起始位置填程序目录
   （用 `pythonw.exe` 可以不显示黑窗口）
5. 设置：勾选「如果任务失败，每隔 1 分钟重启」

**用 NSSM 注册为服务（更稳）**

```bat
nssm install Yunliao "C:\Python312\python.exe" "app.py --host 0.0.0.0 --port 8080 --no-browser --quiet"
nssm set Yunliao AppDirectory "D:\yunliao"
nssm set Yunliao Start SERVICE_AUTO_START
nssm start Yunliao
```

## 6. 反向代理与内网域名

如果不想让同事记 IP，可在内网 DNS 里加一条 A 记录：

```text
chat.corp.local    A    192.168.1.10
```

然后大家访问 `http://chat.corp.local`。

若没有内网 DNS，可让用户在 `C:\Windows\System32\drivers\etc\hosts` 里加：

```text
192.168.1.10    chat.corp.local
```

配置好域名后，在后台「系统设置 → 站点信息 → 绑定域名」里填入，
用于生成正确的分享链接。

## 7. 备份与恢复

### 7.1 备份什么

| 内容 | 位置 | 是否必须 |
|---|---|---|
| 数据库 | `data/app.db`（SQLite）或 `data/mysql/`（MySQL） | **必须** |
| 上传文件 | `data/files/` | **必须** |
| 配置 | `data/config.json` | **必须** |
| 证书 | `cert/` | 用了 HTTPS 就必须 |

### 7.2 用后台备份（推荐）

管理控制台 → 数据库 → 「导出备份」，生成 `backup_YYYYMMDD_HHMMSS.sql`，
下载后异地保存。

这份 `.sql` 是**引擎无关**的：SQLite 导出的可以在 MySQL 上恢复，反之亦然。

恢复：同一页面的「恢复」，选择 `.sql` 文件。系统会先自动备份当前库再恢复。

### 7.3 直接冷备

```bash
# 停服务
sudo systemctl stop yunliao

# 打包
tar czf /backup/yunliao-$(date +%F).tar.gz -C /opt/yunliao data cert

# 启动
sudo systemctl start yunliao
```

Windows 同样：停服务 → 复制 `data\` 和 `cert\` → 启动。

### 7.4 备份策略建议

- **每日**自动冷备数据库 + 配置（体积小，可保留 30 天）
- **每周**全量备份（含上传文件），异地存一份
- **每次升级前**额外做一次完整备份
- 定期**试恢复**到测试机 —— 没验证过的备份等于没有备份

## 8. 升级与回滚

### 8.1 升级

```bash
# 1. 备份（见 §7）
sudo systemctl stop yunliao

# 2. 更新代码（注意：不要覆盖 data/ 和 cert/）
git pull
# 或解压新版本，把 data/ 和 cert/ 保留/拷回

# 3. 启动（会自动做增量表结构迁移）
sudo systemctl start yunliao
```

数据库结构调整是**幂等**的：启动时自动补齐缺失字段，不会破坏已有数据。

### 8.2 回滚

```bash
sudo systemctl stop yunliao
git checkout <上一个版本>
# 用升级前的备份恢复 data/
sudo systemctl start yunliao
```

> 新版若已写入新字段，回滚到旧版一般无碍（旧版会忽略多余字段）。
> 但若新版做了数据搬迁，请用备份恢复。

## 9. 安全清单

上线前逐项确认：

- [ ] **改掉初始管理员密码**，并删除 `data/初始管理员密码.txt`
- [ ] 关闭**自助注册**，或开启「注册需审核」（系统设置 → 注册与账号）
- [ ] 设置口令策略：长度 ≥ 8、开启复杂度要求
- [ ] 调小登录失败锁定阈值（默认 5 次 / 15 分钟）
- [ ] 确认**管理控制台不对普通用户开放**
- [ ] 全站启用 **HTTPS**（至少内网自签）
- [ ] 限制上传类型（`deny_ext` 已默认拦截 `exe/msi/bat/ps1` 等）
- [ ] 按需开启 **IP 白名单**，只允许单位网段访问
- [ ] 确认 `data/` 目录**不可被 Web 直接访问**（云聊自身已隔离，反向代理勿误配）
- [ ] 定期检查**审计日志**
- [ ] 备份文件**不要**放在 Web 可访问的目录
- [ ] 若启用 MySQL，考虑设置 `mysql_password`（见 §3.3）
- [ ] 服务器防火墙只放行必要端口（80/443 或 8080）

## 10. 常见问题

**Q：启动报 `ModuleNotFoundError: No module named 'pymysql'`**
A：只有在 MySQL 模式下会用到。确认 `vendor/pymysql/` 存在；
若不存在，按 §3.3 准备运行时。SQLite 模式不需要它。

**Q：MySQL 模式启动失败，日志里有 `Can't create/write to file 'E:\??\...'`**
A：路径含中文导致 mysqld 解析失败。把程序移到纯英文目录（如 `D:\yunliao`）。
程序虽有目录联接兜底，但英文路径最稳。

**Q：启动提示「未找到证书文件，HTTPS 未启用」**
A：正常现象。默认 `https_enabled` 为 `false`。需要 HTTPS 时按 §4 配置。

**Q：改了 `data/config.json` 但不生效**
A：① 确认是合法 JSON（多余逗号是常见错误，程序会在控制台打印解析失败警告）；
② 大部分配置需**重启**生效；站点名称、主题配色等可在后台在线改，无需重启。

**Q：聊天不实时，要刷新才看到新消息**
A：WebSocket 被中间代理拦了。检查 Nginx 的 `Upgrade` / `Connection` 头（见 §4.3），
或防火墙是否允许 WebSocket。

**Q：忘记管理员密码**
A：`python app.py --reset-admin`，新口令会打印在控制台。

**Q：端口被占用**
A：`python app.py --port 9000`。MySQL 模式的 mysqld 端口会自动避让，无需手动处理。

**Q：上传大文件失败**
A：① 后台「系统设置 → 上传限制」调大 `max_upload_mb`；
② 反向代理的 `client_max_body_size` 也要调大。

**Q：能不能多台机器同时跑，共用一个数据库？**
A：可以做，但需要外部独立 MySQL（不是内置那个），并配置粘性会话，
因为在线状态和会话 token 保存在进程内存。多数内网场景单实例足够。
